# QQ 群管理工具

基于 NapCat / OneBot v11 的本地桌面群务工作台。浏览器操作，Python 标准库后端，资料保存在本机。

## 启动

需要 Python 3.10+。在项目目录运行：

```powershell
python run.py
```

浏览器默认打开 `http://127.0.0.1:8787`。可用 `--port 9000` 换端口，`--no-browser` 不自动打开浏览器。

在 NapCat WebUI 中新建 HTTP 服务器，例如 `127.0.0.1:3000`，设置 Token 并重启 NapCat。在本工具「设置」中填写相同地址和 Token，保存并连接。这里填写 HTTP API 地址，不是 WebUI 的 6099 端口。

基础功能无需第三方依赖；需要 XLSX 时安装可选依赖：

```powershell
python -m pip install -r requirements-xlsx.txt
```

## 工作台入口

- **群聊**：查看群资料，在结果表上方查看成员或管理所选群。
- **成员**：在「人员总览」查看和勾选成员，可切换按人汇总、群内明细与逐群对照。「改群昵称」单独选择来源和目标群。
- **名单与邀请**：在「入群跟踪」管理邀请和导入的名单，在「群关系核对」对照来源名单与待核对群。
- **任务**：查看资料采集和批量修改的进度、逐条结果、审计日志与群昵称快照。连接配置、共享筛选预设和批量参数集中在「设置」。

在「设置 → 外观」可选日间、夜间或跟随系统，连接状态和当前账号显示在侧栏底部。搜索时按回车或点「搜索」，点「清空」只清除关键词。成员表支持双击群标签，或选中标签按 Enter，在群聊目录定位并勾选。

## 共享筛选

群聊目录、成员工作台和群选择器使用同一套“字段 → 条件 → 值”编辑器，支持嵌套的并且、或者、非。

- 文字：包含、正则匹配／不匹配、为空、未提供。
- 数值与时间：比较、范围、最近 N 天、超过 N 天。范围使用逗号分隔，例如 `2026-01-01,2026-12-31T23:59:59`。
- 关系：群内成员、同一个人的群记录，可以选择任一、全部、没有或匹配数量。
- 一个关系组内的条件必须由同一条记录满足；检查不同群时分别添加关系条件。

正则统一使用 Python `re`，标记支持 `i`（忽略大小写）、`m`（多行）、`s`（跨行）。日期按北京时间显示为 `YYYY-MM-DD HH:mm:ss`，正则匹配字段显示文本；原始字段按原值匹配。无效规则会明确报错，不会退回全部记录。

下拉框内置可管理群、收藏群、【师生】群、身份、加群年份、空群昵称、未发言时间、禁言、单群／多群成员、交集、指定群内外关系、昵称来源差异等预设。选择带省略号的预设后编辑参数并应用。

群目录和群选择器只显示适合群对象的内置预设，身份表示当前登录账号在群内的身份。成员工作台保留成员和跨群预设；自定义预设仍共享。修改预设条件后，下拉框立即显示临时筛选，也可更新原自定义预设。

“名称或备注以【标签】开头”使用 `^【[^【】\r\n]+】`，例如匹配 `【活动】话剧《南望永怀》观众`、`【团员】26上 新发展`。筛选栏与改名面板提供「正则帮助」，在新标签页打开 [Python 官方中文正则教程](https://docs.python.org/zh-cn/3/howto/regex.html)。

可将任意组合命名保存成新预设，并在各视图使用；自定义预设可以更新、复制或删除，内置预设可以另存修改。群目录和成员工作台分别记住各自当前条件。成员字段预设用在群目录时，表示“包含匹配成员的群”。

例如“在师生群但不在课程群”：添加一个同一人的群记录条件，要求任一群显示名匹配 `^【师生】`；再添加一组，要求没有群显示名匹配 `^【课程】`。关系检查针对查看范围内的群，请将相关群加入查看范围。

## 完整资料与按需补全

基础读取群列表和成员列表。群信息、群详细信息、群扩展信息、逐人成员详情，以及禁言、荣誉、全体提醒额度等管理状态，可在工作台补全；依赖未采集字段的筛选会先补全所需资料，再返回完整结果。

加载或刷新群目录、成员名单、群选择器、群关系核对、群昵称及群设置预演时，立即显示进度。耗时读取在后台运行，按实际完成的群数显示读取身份、备注、成员名单等阶段；总量尚未知时显示进行中的进度条与已用时间，不模拟百分比。任务列表、详情及页面进度统一每秒刷新，失败会结束加载状态并保留错误提示。

资料采集进入任务中心，使用 4 个并发只读请求，可中止、重试失败项。界面区分未采集、采集失败、不支持、未提供和实际空值；接口失败不会被当成成员未加入或未禁言。具体可取得的字段取决于 NapCat 版本和当前账号权限。

资料接口的完整响应按账号、群和接口分别落盘。常用字段统一显示，未知字段进入扩展字段，可以选择显示、筛选和导出；资料抽屉中可查看原始内容与接口状态。本次不采集聊天记录、文件、相册、公告内容或入群申请列表。

基础名单使用内存与磁盘缓存，旧缓存有提示；需要最新名单可点刷新，群昵称预演会重新读取。收藏、列选择、分组和视图条件保存在当前浏览器，连接配置、模板和筛选预设保存在本地配置文件。

## 人员总览、群关系核对与长列表

「人员总览」默认按 QQ 合并，一人一行显示所在群数和群摘要；点击各群资料查看实际群昵称、身份和完整资料。在表格上方切换「群内明细」可查看每人每群一条记录，切换「逐群对照」可比较各群字段。人员总览、群关系核对和改群昵称分别记住配置。人员总览的群数只统计自己选定的群。

群目录中双击某群的记录可直接进入该群的「群内明细」，清除上次的成员筛选和搜索，显示该群全部成员。群目录与成员列表的当前排序列以箭头标明升降序，底部也显示排序依据。拖动表头右边界调整列宽，按账号和列表类型保存在当前浏览器；双击边界恢复默认宽度，也可聚焦边界后用方向键微调（Shift 加大步长）。

群聊名称、来源和逐群对照使用按账号、群号保存的颜色标签；采用经典 Category10 起步的 256 色 Glasbey 色板，优先分配差异较大的颜色，不同群不会因哈希取模而撞色。用完 256 色后以不同亮度继续区分，名称、备注、排序变化均保持已分配颜色。色板来自 [Colorcet 3.2.1](https://colorcet.holoviz.org/user_guide/Categorical.html)，本地附带 CC-BY-4.0 授权与来源，运行时无需联网；身份、核对结果、禁言与采集状态同时以文字和不同颜色显示。成员详情分为「个人资料」「在本群的信息」「群聊资料」，原始接口资料也按成员与群聊分别展开。

在「名单与邀请 → 群关系核对」，先选择名单来源群（默认【师生】群），用「来源成员条件」筛选后按 QQ 合并去重。分别核对待核对群中的缺少、名单外、共有人员。左侧列出每个目标群的统计，右侧查看、搜索、复制和导出当前群的核对结果。名单外仅表示不在本次来源名单中，不自动移除成员，也不邀请缺少的人。核对配置可命名保存到当前账号的浏览器。

「改群昵称」明确分开读取昵称的来源群和准备修改的目标群；来源按优先级采用第一个非空值，冲突不会隐藏，列表与预演显示采用哪个群的哪段文本。来源群只读，不参与同步修改。模板和 CSV 方式不需要昵称来源群。

所有主要结果表提供完整滚动条，后台首次查询生成固定结果，之后每次只读取当前位置所需的 200 行窗口，不重复扫描全部成员。前端只渲染屏幕附近的行，逐群对照同时虚拟化群列，固定 QQ 和昵称等身份列。分组标题独立显示，详情在抽屉展开。表格底部显示「资料读取时间」和旧缓存状态：单次读取显示实际取得基础群列表／成员名单的时间，多群分批读取显示最早至最晚时间范围，统一按北京时间显示，不把查询生成时间当成资料更新时间；改变条件或刷新才生成新查询。

表头复选框会全选当前筛选的全部记录，包括尚未显示的行，再次点击可取消当前筛选内的勾选。更改主表搜索、筛选、状态或目标时清空勾选。表格上方的「操作范围」在有勾选时默认使用勾选记录，否则使用全部筛选结果，可手动切换。读取失败时可在页面上重试。查询结果按连接和账号隔离，服务最多保留 8 份，闲置 30 分钟释放，失效时提示重新加载。

群选择器的最终范围只包含当前筛选内已勾选的群。切换筛选后，筛选外的勾选保留为本次窗口的暂存，不会混入最终查看、核对或改名范围；底部持续显示最终范围数量、当前筛选数量和筛选外暂存数量，应用按钮显示实际要应用的群数。展开「筛选外暂存」可逐群取消或一键清空，也可勾选「显示全部筛选外群」并搜索、勾选其他群，无需改动主筛选。再次切换筛选时，匹配到的暂存勾选会重新计入最终范围；关闭或应用窗口后只保留已应用的群范围。

列表到达顶部或底部后，继续滚动会接着滚动外层页面或抽屉，便于查看筛选栏、暂存区域和其他内容。

旧工作台查看范围迁移到人员总览，原基准群和优先级迁移到改群昵称，旧跨群链接进入人员总览；原筛选预设、模板与群昵称快照继续可用。

## 批量改群昵称

1. 在「改群昵称」任务中分别选择昵称来源与目标群，应用共享条件并选择操作范围。
2. 点击「预演并改名」，使用同步来源、变量模板或 CSV 名单。
3. 可以从文本字段提取捕获组或做正则替换，再套用最终模板。
4. 先预演检查旧昵称、新昵称、来源和跳过原因，再试改或全量执行。

常用变量：`{result}` 为源文本／正则结果，另支持 `{nickname}`、`{card}`、`{qq}`、`{group_name}`、`{index}`、`{level}`、`{join_year}`、`{title}`。

例如源文本为 `26级-张三-1班`，提取正则 `^\d+级-(.+?)-.*$` 的第 1 组，最终模板 `{result}`，得到 `张三`。命名捕获组可使用 `(?P<name>...)`，替换文本可使用 `\g<name>`。

未匹配、结果为空、无对应来源文本、权限不足和昵称相同都会跳过；“只补空群昵称”使用同一套条件计算。CSV 使用两列 `QQ号,新群昵称`，有无表头均可。

同步方式只修改目标群。群昵称按 40 字符上限截断并提示；群主与管理员的修改限制沿用原权限判断。默认每条间隔 2 秒、失败重试 2 次、试改前 10 条；超过 100 条需要再次确认，可在设置调整参数。

执行固定预演过的目标与新群昵称，重新检查当前成员和权限；多群共用一个串行写任务，每个目标群分别保存原昵称快照。任务中心可按群回滚。

## 批量群设置与管理员

在群聊目录勾选目标群，点击「群设置」。窗口分为基本资料、加群与邀请、管理员三个分类，右侧集中显示逐群差异；顶部可展开核对群号和当前账号身份。空白文本与「不修改」保留现有设置。

- 基本资料：群名称、群头像、全员禁言、通过群号搜索、发布新群公告。群名与公告支持 `{group_name}`、`{group_id}`；公告为新增发布。
- 加群方式：允许任何人加入、禁止任何人加入、发送验证消息、回答问题并由管理员审核、正确回答问题自动加入。只有两个问答模式需要问题，自动加入还必须填写正确答案；切换方式后，不发送无关问题和答案。
- 成员邀请：禁止、需要管理员审核、无需审核、群人数少于 100 时无需审核，均可批量设置。
- 管理员：按 QQ 号批量添加或取消管理员；修改指定 QQ 或各群全部现有管理员的验证消息接收、撤回成员消息、移除成员权限。开启移除权限时可选每日不限、5、10、20、50、100、200 人。群主验证消息提醒可单独选择；不修改群主身份。

管理员操作需要当前账号是群主。预演重新读取各群身份与成员，显示未入群、已是／已非管理员、权限不足、无变化、接口不支持或读取失败的原因；不会为设置权限自动授予管理员身份。先添加管理员并等待任务完成，再设置其细分权限。

**协议能力有区别**：NapCat 支持管理员增删、五种加群方式和成员邀请策略，但未提供单个管理员细分权限及验证消息开关。细分权限通过设置中的 **SnowLuma** 适配器接入 `get_group_admin_permissions`、`set_group_admin_permissions`、`set_group_admin_receive_verify`；需要协议端提供这些接口。群主提醒也使用该验证消息接口，协议端拒绝或读取失败会跳过。旧版本或其他协议端不支持的项目会明确跳过，其他可执行项目仍可提交，不将不支持项显示为成功。

接口映射参考 [NapCat 加群设置源码](https://github.com/MingTianSang/NapCatQQ/blob/main/packages/napcat-onebot/action/extends/SetGroupAddOption.ts)、[NapCat 邀请策略源码](https://github.com/MingTianSang/NapCatQQ/blob/main/packages/napcat-onebot/action/group/SetGroupMemberInvitePolicy.ts) 与 [SnowLuma SDK 权限说明](https://www.npmjs.com/package/@snowluma/sdk)。通过群号搜索使用扩展接口，实际支持取决于协议端版本。

设置模板可保存、更新、另存和删除，旧模板仍可加载。预演只读，修改操作配置后须重新预演；预演完成后可直接点击「执行变更」，不再要求额外勾选核对框。服务保存绑定当前账号的预演，30 分钟内有效，重启失效；执行前重查设置和权限，目标操作变化会要求重新预演，同一份预演只能提交一次。任务按原批量间隔串行执行，逐项结果在任务中心查看；设置快照保存预演内容用于核对，不支持自动回滚。

## 导出

复制为制表符表格，可粘贴到 Excel / WPS；CSV 使用 UTF-8 BOM，XLSX 为可选依赖。显示字段和导出字段使用同一目录，导出使用同一套筛选与操作范围，不受分页或原有 5000 人限制。跨群导出明确标注未加入。

## 按名单勾选与入群跟踪

在「成员 → 人员总览」选好来源群，点「按名单勾选」，粘贴 Excel/WPS 或 Markdown 表格，也可以上传 CSV、TSV 或 XLSX。工具从群昵称提取字段，以姓名加班级、学号、手机号或表格中的 QQ 号匹配，唯一结果可以批量确认。同名或证据冲突的行需要人工处理。匹配后可导出勾选记录，点击「发起邀请」，或在「成员管理」里预演禁言、移出。

邀请通过 QQ 私聊发送现有目标群的入群链接。预演会提示已知的加群限制，以及 SnowLuma 收件人是否需要群临时会话。发起邀请或选择「仅保存入群跟踪」后，工作台打开「名单与邀请 → 入群跟踪」里的对应计划。「继续邀请」按表格上方的操作范围预演当前筛选结果或勾选记录。

1. 若只需要手动跟踪，打开「名单与邀请 → 入群跟踪」，导入成员 CSV、TSV、XLSX 文件，或粘贴「复制表格」的内容。
2. 保留导出表头和 `QQ号` 列，列顺序不限，其他导出字段全部保留。支持人员总览、群内明细和逐群对照的成员导出，重复 QQ号合并为一人，各列采用第一个非空值；无效行会报出行号，修正后再导入。
3. 预览后保存建群计划，在 QQ 客户端创建群聊，再填写群号绑定。也可以绑定当前账号已加入的现有群。
4. 绑定时立即读取最新群成员，显示应到、已入群、未入群、已退群和待核对人数。页面打开且可见时默认每 30 秒重新核对，可关闭自动核对或点击「立即核对」。
5. 按状态或名单内容筛选，再按操作范围复制或导出名单。选择「未入群」包含之前已入群、现在已退群的人。

名单和核对记录按 QQ账号保存在 `data/rosters/`，重启后继续使用。首次核对前显示「待核对」；读取失败保留上次成功结果和时间，并显示错误，不能据此判断最新是否入群。首次／最后确认在群时间为本工具成功核对的时间，另列显示协议端提供的本次加群时间；两次核对之间的短暂进出无法记录。换绑其他群会重新记录首次确认时间。删除本地计划只删除对应名单与跟踪记录。

当前采用 QQ 客户端建群并绑定的流程：NapCat 和 SnowLuma 的公开接口未提供可直接调用的创建 QQ群或主动邀请成员接口；邀请策略和“允许成员发起新群聊”属于群权限设置。[NapCat 接口目录](https://napcat.apifox.cn/)、[SnowLuma 群成员权限](https://snowluma.github.io/zh/docs/api/group-admin/set_group_member_permissions)。两者都可通过成员列表接口完成本功能的入群核对。XLSX 导入与导出共用可选依赖 `openpyxl`。

共享模块：`app/core/fields.py`（字段）、`app/core/filters.py`（条件树）、`app/services/query.py`（查询）、`app/services/collection.py`（补全）、`app/services/rename.py`（群昵称生成）。前端共享 `filters.js`、`workspace.js`、`actions.js`、`result-table.js` 和 `result-windows.js`。虚拟化使用本地 TanStack Virtual Core 3.19.11（MIT，`web/vendor/tanstack-virtual-core/`），运行时无需联网或 Node.js。更新时从 npm 固定版本包复制 `dist/esm/*.js` 与 LICENSE，将 `process.env.NODE_ENV` 替换为字符串常量 `"production"`，并更新 VERSION。

统一接口包括 `POST /api/query`（原分页接口保留）、`POST /api/query/start`（创建长列表查询）、`GET /api/query/results/{query_id}`（读取窗口）、`GET /api/query/results/{query_id}/selection`（全部筛选记录 ID）、`POST /api/members/compare`（名单核对）、`POST /api/query/export`（支持 query_id）、`GET /api/fields`、筛选预设 CRUD、`POST /api/data/collect` 和群昵称预演／执行接口。旧任务与快照接口继续可用。

## 本地数据与使用说明

`config.json` 保存连接、运行参数、模板和筛选预设；`data/cache/` 保存账号隔离的资料缓存，`data/rosters/` 保存建群名单与入群跟踪记录，`data/snapshots/` 保存修改前快照，`data/logs/` 保存任务汇总日志。这些运行数据均不纳入版本管理。

任务队列与逐条结果保存在内存中，重启后不恢复；每个任务最多保留 5000 条结果，但操作数量与资料导出不受这个展示限制。Token 不返回前端，逐条成员操作结果不落审计日志。

服务仅监听本机，不要映射到公网。导出包含成员资料，应妥善保管。非官方协议端存在账号风险，批量操作建议使用专门的管理号。
