# QQ 群管理工具

基于 NapCat（OneBot v11 HTTP）的本地群务工具，浏览器里操作，数据全部留在本机。

主要功能：

- **群组列表**：群头像、搜索、只看可管理、收藏置顶（本地记忆）、勾选多个群批量操作
- **群备注**：可切换「显示群备注」，有备注的群直接以备注作为名称
- **正则自动分组**：按当前显示名匹配正则（默认取 `【】` 内的内容）自动分组，未命中的归入「未分组」
- **群成员表格**：搜索、按身份/入群年份筛选、排序、分页、多选
- **导出**：CSV（Excel 直接打开不乱码）/ XLSX，字段可选，范围可选全部/筛选结果/勾选；
  支持**一键复制到剪贴板**（制表符分隔，直接粘进 Excel），并记住上次选的字段与格式
- **多群导出**：勾选多个群合并成一张表，每行带群号 / 群名
- **共同群成员**：同时对比多个群，找出交集成员，并按群展示名片 / 身份 / 加群时间
- **本地缓存**：群列表与成员名单落盘缓存，重开页面秒出，后台自动刷新
- **批量改名片**：模板变量、范围筛选、CSV 名单导入、**先预演后执行**、限速重试、可中止、自动快照与一键回滚
- **群设置模板**：群名、群公告、全员禁言、群头像、加群方式、群搜索，可一次套用到多个群，逐群差异预览
- **任务中心**：执行进度、逐条结果（内存）、任务汇总审计日志、名片快照回滚

## 一、准备工作

### 1. 需要 Python 3.10+

基础功能仅依赖 Python 标准库，无需安装第三方包。CSV 导出和复制到剪贴板可直接使用；
XLSX 导出需额外安装 `openpyxl`（见启动步骤）。

```powershell
python --version
```

### 2. 在 NapCat 里开启 HTTP 服务

1. 启动 NapCat，打开 WebUI：`http://127.0.0.1:6099`
2. 进入「网络配置」→ 新建 → **HTTP 服务器**
3. 填写：
   - Host：`127.0.0.1`
   - Port：`3000`（被占用就换 `3002`）
   - Token：自己设一串，别留空
   - CORS：不用开（本工具有后端代理，不走浏览器直连）
4. 保存后**重启 NapCat**
5. 回到本工具「连接」页，填同样的地址与令牌，点「保存并连接」

### 3. 权限要求

改名片需要机器人账号在目标群是**群主或管理员**。以下情况会被自动跳过，不会刷一屏失败：

- 群主的名片无法修改（任何人都不行）
- 管理员无法修改其他管理员和群主的名片
- 名片本来就和模板结果一致

## 二、启动

下载本仓库 ZIP 并解压后，在包含 `run.py` 的目录打开终端，执行 `python run.py`。
也可以使用 Git 克隆：

```powershell
git clone https://github.com/efds5694/qq-group-manager.git
cd qq-group-manager
python run.py
```

需要 XLSX 导出时，建议先创建虚拟环境并安装可选依赖：

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements-xlsx.txt
.venv\Scripts\python run.py
```

Linux / macOS 可将 `python` 换成 `python3`，虚拟环境中的解释器路径为 `.venv/bin/python`。
未安装可选依赖时，界面仅提供 CSV 导出，其他基础功能正常使用。

浏览器会自动打开 `http://127.0.0.1:8787`。常用参数：

```powershell
python run.py --port 9000      # 换端口
python run.py --no-browser     # 不自动开浏览器
```

关闭命令行窗口即停止服务。批量任务共用一个工作线程按提交顺序执行。
任务队列和逐条结果保存在内存中，重启后清空，未完成的任务不会自动恢复；
日志和快照保存在 `data/`，重启后仍保留。

## 三、使用流程

### 导出成员

群组 → 选群 → 成员页右上「导出」→ 勾字段、选格式 → 开始导出（或「复制到剪贴板」）。
文件落在浏览器默认下载目录；字段与格式会被记住，下次打开保持不变。

### 多群导出 / 共同成员

群组页勾选多个群（卡片右上角复选框），底部会浮出操作条：

- **导出成员**：把选中的群合并成一张表，每行带群号 / 群名，可在 Excel 里筛选
- **共同成员**：求这些群的成员交集，列表按群展示群名片 / 身份 / 加群时间，可搜索、复制、导出

群组页顶部还有「只看可管理」（隐藏自己没有管理权限的群）和「只看收藏」，卡片上的星标可收藏群，
收藏的群会排在前面。

### 群备注与自动分组

群组页工具栏：

- **显示群备注**：有群备注的群，卡片标题直接显示备注，原群名放到下面一行（备注来自 NapCat 的
  `get_group_info`，首次进入会懒加载一次并缓存；协议端不提供该字段时自动退回群名）
- **自动分组**：按当前显示的名称匹配正则，取第一个捕获组作为分组标题，未命中的群归入「未分组」
  - 默认正则 `^【(.+?)】`，即 `【师生】23级（本）`、`【师生】24级（本）` 都会归到「师生」组
  - 想按别的前缀分组就改这个输入框，例如 `^(\d{2}级)`、`^(.+?)[-_]`
  - 正则写错时输入框会标红，列表临时按全部显示

卡片右上角还可以收藏（星标）或勾选（用于批量导出 / 共同成员）。

### 批量改名片（推荐流程）

1. 成员页勾选目标成员，或直接进「批量改名」按范围筛选
2. 填模板，例如 `{nickname}-2026`、`{group_name}·{nickname}`、`{index}_{nickname}`
3. 点「预演差异」，检查「旧名片 → 新名片」对照表与跳过原因
4. 点「试改前 10 人」，去群里确认效果
5. 确认无误后点「全量执行」（超过 100 人需要二次确认）

可用变量：

| 变量 | 含义 |
|---|---|
| `{nickname}` | 成员昵称 |
| `{card}` | 原群名片（可用于加前缀/后缀） |
| `{qq}` | QQ 号 |
| `{group_name}` | 群名称 |
| `{index}` | 本次处理序号 |
| `{level}` | 活跃等级 |
| `{join_year}` | 入群年份 |
| `{title}` | 群头衔 |

名片上限按 40 字符处理，超出自动截断并在预演里提示。

### 按名单改名片

准备一个 CSV（UTF-8），两列，无表头也可以：

```
10001,张三-技术组
10002,李四-运营组
```

在「作用范围」选「按导入名单」，上传文件后预演。

### 群设置模板

「群设置」页填模板 → 右侧勾选目标群 → 「生成差异」→ 确认无误 → 「套用模板」。
不支持的项目会自动置灰并标注原因（例如协议端没有群公告接口）。

### 回滚

「任务中心」→ 快照列表 → 找到对应的改名片快照 → 「回滚」。
回滚会把快照里的成员名片逐个恢复为改动前的值，同样受限速约束。

## 四、参数与配置

`config.json`（首次保存配置时自动生成）：

```json
{
  "active_profile": "NapCat",
  "profiles": [
    { "name": "NapCat", "base_url": "http://127.0.0.1:3000", "token": "", "adapter": "napcat" }
  ],
  "batch": { "interval": 2.0, "retries": 2, "trial_size": 10, "min_interval": 0.8, "max_interval": 10.0 },
  "templates": [],
  "server": { "host": "127.0.0.1", "port": 8787 }
}
```

- `batch.interval`：每条之间等待的秒数，默认 2 秒。**不要低于 1 秒**，容易触发风控。
- `batch.retries`：单条失败重试次数（指数退避）。
- 多个 QQ 号可以存多个 profile，在连接页切换。

## 六、常见问题

| 现象 | 原因与处理 |
|---|---|
| 连不上 127.0.0.1:3000 | NapCat 未启动，或没开 HTTP 服务，或端口被占。用 `netstat -ano \| findstr :3000` 看谁占着。 |
| 提示「返回的不是 JSON」 | 地址填成了 WebUI 端口（6099）。要填 HTTP API 端口（3000）。 |
| 全部改名片失败，retcode 1400 | 机器人不是管理员；或目标是群主（不可改）。 |
| 提示操作过于频繁 / retcode 1200 | 被风控。立即停止，把间隔调到 3~5 秒，等一段时间再试。 |
| 成员列表很久不出来 | 大群首次拉取要几秒。超过 30 秒会超时，刷新重试。 |
| 导出 Excel 打开乱码 | 用工具导出的 CSV 已带 BOM；如果是自己另存过，注意编码。 |
| 群公告/头像按钮灰掉 | 协议端不支持该扩展接口，属正常降级。 |

## 七、安全说明

- 服务默认监听 **127.0.0.1**；`--host` 与配置中的 `server.host` 仅接受 `127.0.0.1` 或 `localhost`，拒绝 `0.0.0.0`。不要做端口映射或反向代理到公网。
- Token 保存在本机 `config.json`，不会返回给前端页面。
- 落盘审计日志记录连接事件、任务完成或取消的汇总信息（计数、耗时等），不保存逐条成员操作结果，也不记录 token 与完整响应。逐条结果仅保留在内存中，每个任务最多 5000 条，重启后清空。
- 导出的成员名单包含 QQ 号，属于个人信息，请勿外传。
- 使用非官方协议端本身违反 QQ 用户协议，存在账号风险。建议用专门的管理号，不要在主力号上跑批量操作。

## 八、换成别的协议端

只改 `app/onebot/adapters.py` 里的映射表，然后把连接页的「协议端类型」切过去。业务代码不用动。

已预置：

- `napcat`：全部能力
- `llonebot`：无群搜索选项
- `lagrange`：无加群选项、无群搜索选项

如果新协议端连群公告的接口名都不同，在 `ADAPTERS` 里加一项即可，`probe.py` 会自动探测群公告能力并决定界面是否显示。
